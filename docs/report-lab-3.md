## 1. Мета роботи

Опанувати керування розкладкою засобами Flexbox і Grid та побудувати основну
сітку інтерфейсу проєкту.

## 2. Що зроблено

До всіх трьох сторінок застосовано спільний каркас: шапка, два стовпці вмісту
(основна частина та бічна панель) і підвал. На головній сторінці та на сторінці
«Про проєкт» додано багатоколонкову сітку карток. Усе оформлення лишилося в
одному зовнішньому файлі `assets/css/style.css` — вбудованих стилів у розмітці
немає.

## 3. Каркас сторінки

Тег `body` отримав клас `page` і став grid-контейнером на три рядки:

```css
.page {
    display: grid;
    grid-template-rows: auto 1fr auto;
    min-height: 100vh;
}
```

Шапка і підвал займають стільки, скільки потрібно їхньому вмісту, а середній
рядок забирає залишок висоти. Через це підвал притиснутий донизу навіть на
короткій сторінці — класична задача «липкого підвала», яка раніше вимагала
обхідних прийомів із `position: absolute` або від'ємними відступами.

Перевірка: на вікні заввишки 2000 px нижня межа підвала теж дорівнює 2000 px,
тобто порожнього місця під ним не залишається.

## 4. Вміст і бічна панель

Обгортка `.layout` ділить середній рядок на два стовпці:

```css
.layout {
    display: grid;
    grid-template-columns: minmax(0, 1fr) var(--sidebar-width);
    gap: 40px;
    align-items: start;
}
```

Перший стовпець гнучкий, другий має сталу ширину 260 px. На вікні 1200 px це
дає 740 px і 260 px відповідно.

Чому `minmax(0, 1fr)`, а не просто `1fr`: значення `1fr` за замовчуванням не
дозволяє стовпцю стиснутися вужче за його вміст, тому довге слово або широка
таблиця всередині здатні розсунути сітку й викликати горизонтальне
прокручування. Запис `minmax(0, 1fr)` знімає це обмеження.

`align-items: start` потрібен, щоб бічна панель не розтягувалася на всю висоту
основного стовпця: за замовчуванням у Grid елементи розтягуються.

У розмітці `aside` стоїть після `main`, тому при переході в один стовпець
бічна панель опиняється під основним текстом, а порядок обходу з клавіатури
збігається з порядком читання.

## 5. Сітка карток

```css
.cards {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
    gap: var(--gap);
}
```

Кількість стовпців браузер добирає сам: він вміщує стільки колонок завширшки не
менше 220 px, скільки влізає, а залишок ширини ділить між ними порівну. Окремі
точки зламу для сітки карток не потрібні взагалі — виміряно, що при ширині вікна
1200 px виходить три колонки по 233 px, при 850 px — три по 251 px, при 375 px —
одна.

Різниця між `auto-fit` і `auto-fill` саме тут непомітна, бо карток більше, ніж
колонок. Вона проявилася б, якби карток було менше: `auto-fill` залишив би
порожні колонки, а `auto-fit` розтягує наявні картки на всю ширину.

## 6. Де Grid, а де Flexbox

Критерій простий: Grid — коли розкладку задає контейнер і потрібні рядки й
стовпці одночасно; Flexbox — коли елементи шикуються в один напрямок, а їхні
розміри визначає власний вміст.

| Місце | Інструмент | Чому так |
| --- | --- | --- |
| Каркас сторінки | Grid | три рядки сталої структури, середній розтягується |
| Вміст і бічна панель | Grid | два стовпці заданої пропорції |
| Сітка карток | Grid | двовимірна сітка, кількість колонок залежить від ширини |
| Шапка | Flexbox | два блоки в рядок, назва ліворуч, меню праворуч |
| Нутрощі картки | Flexbox | один стовпець, елементи різної висоти |
| Ряд тегів | Flexbox | елементи різної ширини з переносом на новий рядок |
| Бічна панель | Flexbox | блоки один під одним з однаковим проміжком |

Окремо варто пояснити картку:

```css
.card {
    display: flex;
    flex-direction: column;
}

.card__link {
    margin-top: auto;
}
```

Текст у картках різної довжини, і без цього посилання «пливли» б на різній
висоті. `margin-top: auto` у flex-контейнері з'їдає весь вільний простір над
елементом і притискає його до низу. Самі картки вирівнюються між собою
автоматично: Grid за замовчуванням розтягує елементи рядка на однакову висоту —
виміряно, що всі чотири картки мають висоту 229 px.

## 7. Точки зламу

Їх дві, обидві задані за змістом, а не під конкретні моделі пристроїв:

- **900 px** — ширини перестає вистачати на два стовпці, тому `.layout`
  переходить в один і бічна панель іде під текст.
- **600 px** — шапка стає стовпчиком, поля «Ім'я» та «Електронна пошта»
  розгортаються з двох колонок в одну, кнопка займає всю ширину.

Сітка карток у медіазапитах не згадується: вона перебудовується сама.

## 8. Помилка, знайдена під час перевірки

Перевіряючи сторінки на ширині 375 px, виявив горизонтальне прокручування:
`scrollWidth` дорівнював 395 px при вікні 375 px. Причина — правило
`width: 100%` разом із `padding: 10px 20px` на кнопці та полях форми. За
типовим `box-sizing: content-box` відступи додаються до заданої ширини, тому
елемент виходив на 40 px ширшим за контейнер.

Виправив загальним правилом:

```css
*,
*::before,
*::after {
    box-sizing: border-box;
}
```

Тепер відступи й рамка рахуються всередині заданої ширини. Після виправлення
`scrollWidth` дорівнює 375 px на всіх трьох сторінках.

Помилка з'явилася ще в попередній роботі, коли до кнопки додалося
`width: 100%`, і тоді її не помітив — на око сторінка виглядала нормально,
зайві 20 px давали лише ледь помітне прокручування.

## 9. Окремий файл стилів

Усе оформлення лежить в `assets/css/style.css`. Перевірив пошуком: атрибутів
`style` у розмітці немає жодного на всіх трьох сторінках. Файл поділено на
іменовані блоки коментарями: змінні, базові стилі, доступність, каркас,
шапка, картки, теги, бічна панель, форма, підвал, медіазапити.

Повторювані величини винесено у змінні `--page-width`, `--sidebar-width`,
`--gap`: ширина бічної панелі згадується у двох місцях, проміжок — у шести,
і тримати їх в одному місці дешевше, ніж шукати по файлу.

## 10. Перевірка валідатором розмітки

Після перебудови розкладки всі три сторінки перевірено валідатором W3C
(`validator.w3.org/nu`). Результат:

| Сторінка | Помилки | Попередження |
| --- | --- | --- |
| `index.html` | 0 | 0 |
| `about.html` | 0 | 0 |
| `contact.html` | 0 | 0 |

Перевірка була не формальністю: у цій роботі з'явилися місця, де помилку легко
допустити.

- Картки оформлені як `li` всередині `ul` з класом `cards`. Grid-контейнером
  тут виступає сам список — це коректно, бо `display: grid` не змінює
  дозволених вкладень. Якби я поклав картки у `div` усередині `ul`, валідатор
  видав би помилку: `ul` допускає лише `li`.
- Обгортка `.layout` — звичайний `div` між `header` і `footer`, усередині
  нього `main` і `aside`. Обидва теги дозволені в цьому місці, і `main` на
  сторінці лишається один.
- Бічна панель містить заголовки `h2`, тож рівні заголовків на сторінці не
  ламаються: `h1` в основному вмісті, `h2` у секціях і панелях, `h3` у картках.

## 11. Відоме обмеження

Шапка, бічна панель і підвал усе ще повторюються в трьох файлах. Обсяг
дублювання зріс: бічна панель — це ще близько двадцяти рядків на сторінку.
Засобами HTML і CSS це не розв'язується, потрібна збірка сторінок, і саме тому
вона стоїть у плані окремим етапом.

## 13. Висновки

Сітку інтерфейсу побудовано на Grid, вирівнювання всередині блоків — на
Flexbox, і кожен із двох інструментів застосований там, де він дає коротший
запис. Сітка карток обходиться без медіазапитів, бо кількість колонок браузер
визначає сам. Перевірка на вузькому екрані виявила давню помилку з
`box-sizing`, яку виправлено одним загальним правилом. Наступний етап —
інтерактивність на JavaScript; розмітка й сітка для неї вже готові.
