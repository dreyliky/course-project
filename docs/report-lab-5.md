## 1. Мета роботи

Додати до проєкту клієнтську логіку: обробку подій, динамічну зміну DOM та
отримання даних із зовнішнього джерела.

## 2. Що зроблено

З'явилася сторінка «Активність», яка під час відкриття звертається до
публічного GitHub API і показує останні тридцять комітів самого цього
репозиторію. Список можна фільтрувати за типом зміни, подробиці коміту
відкриваються в модальному вікні. У шапці всіх сторінок додано перемикач теми
з трьома станами, вибір зберігається між візитами.

Зовнішнім джерелом узято API самого репозиторію свідомо: сторінка показує
реальні дані про проєкт, які змінюються після кожного пуша, а не вигаданий
набір записів.

## 3. Структура клієнтського коду

| Файл | Відповідальність |
| --- | --- |
| `theme.js` | перемикач теми, читання й запис вибору |
| `api.js` | запит до GitHub API і перетворення відповіді |
| `format.js` | форматування дати для показу |
| `modal.js` | модальне вікно з подробицями |
| `commits.js` | список, стани завантаження, фільтр |
| `main.js` | точка входу сторінки активності |

Код розділено за відповідальністю, а не за сторінками: `api.js` нічого не знає
про DOM, `modal.js` — про те, звідки взялися дані. Форматування дати винесено
в окремий `format.js`, бо його потребують і список, і вікно: якби воно лишилося
в `modal.js`, модулі посилалися б один на одного по колу.

Використано модулі ES (`<script type="module">`). Збірки проєкт не має, тому
модулі підключаються браузером напряму — це працює без інструментів і дає
правильну область видимості: жодна функція не потрапляє в глобальний простір.

## 4. Перемикач теми

Кнопка перебирає три стани: «як у системі» → «світла» → «темна». Системний
стан — це не окреме значення кольорів, а **відсутність** атрибута `data-theme`
на `html`: коли атрибута немає, рішення ухвалює медіазапит
`prefers-color-scheme` з попередньої роботи.

У CSS це дало два селектори замість одного:

```css
@media (prefers-color-scheme: dark) {
    :root:not([data-theme="light"]) { ... }
}

:root[data-theme="dark"] { ... }
```

Уточнення `:not([data-theme="light"])` — саме те, що дозволяє користувачеві
ввімкнути світлу тему на системі з темною. Без нього медіазапит перебивав би
вибір користувача.

**Чому `theme.js` підключений синхронно в `<head>`, а не як модуль.** Модулі
виконуються після розбору документа — як скрипт із `defer`. Сторінка встигла б
показатися у світлій темі й лише потім перемкнутися на збережену темну, тобто
блимнула б при кожному завантаженні. Синхронний скрипт у `<head>` виставляє
атрибут до першого малювання. Решта коду такої вимоги не має і підключена
модулем перед `</body>`.

**Сховище.** Вибір лежить у `localStorage`. Звернення до нього загорнуті в
`try/catch`: у приватному режимі або при заборонених даних сайту сам доступ
кидає помилку, і без перехоплення вона зламала б решту скрипта. При збої
перемикач далі працює, просто вибір не переживає перезавантаження.

## 5. Отримання даних

```js
const response = await fetch(API_URL, { headers: { Accept: 'application/vnd.github+json' } });
```

Важлива особливість `fetch`, яку довелося врахувати: він вважає помилкою лише
збій мережі. Відповідь із кодом 404 або 500 для нього — успішний результат, і
`try/catch` її не спіймає. Тому перевірок дві: `catch` для мережі й окрема
перевірка `response.ok` для кодів відповіді.

З відповіді беруться лише потрібні поля — хеш, перший рядок повідомлення,
решта тексту, автор, дата, посилання. Тип зміни визначається з повідомлення:
усе до двокрапки. Завдяки цьому решта коду не залежить від того, скільки полів
насправді віддає GitHub.

## 6. Стани очікування й помилки

Сторінка має чотири стани: завантаження, помилка з кнопкою повтору, порожній
результат фільтра й сам список. Повідомлення про помилку підбирається за кодом
відповіді, бо користувачеві потрібно розуміти, чи має сенс повторювати спробу.

Перевіряв підміною `fetch` у консолі браузера — кожен випадок відтворено
штучно, а не вгадано:

| Випадок | Повідомлення |
| --- | --- |
| Збій мережі | Не вдалося звʼязатися з GitHub. Перевірте підключення до мережі. |
| 403 або 429 (ліміт) | GitHub тимчасово обмежив кількість запитів. Спробуйте за кілька хвилин. |
| 404 | Репозиторій не знайдено за вказаною адресою. |
| 503 | GitHub зараз не відповідає. Це не помилка сторінки. |
| Відповідь не масив | GitHub повернув відповідь несподіваного вигляду. |

Після кожної помилки кнопка «Спробувати ще раз» повертає список: перевірено,
що після п'яти підряд помилок звичайний запит знову дає 29 карток і сім
фільтрів.

## 7. Фільтрація

Кнопки фільтра не задані в розмітці, а будуються з самих даних: типи
збираються з завантажених комітів через `Set`. Показувати кнопку типу, якого в
списку немає, сенсу не має, а при зміні угоди про повідомлення комітів список
кнопок оновиться сам.

Обраний стан несе атрибут `aria-pressed`, а не лише колір. Він одночасно
слугує селектором для оформлення і повідомляє зчитувачеві екрана, яка кнопка
натиснута — окремий клас для цього не потрібен.

## 8. Модальне вікно

Використано тег `dialog` і метод `showModal()`. Браузер при цьому сам:

- замикає фокус усередині вікна, поки воно відкрите;
- закриває вікно клавішею `Esc`;
- повертає фокус на кнопку, з якої вікно відкрили;
- приховує решту сторінки від допоміжних технологій.

Перевірено: після `Esc` фокус повернувся саме на ту кнопку «Подробиці», якою
вікно відкривали. Написане вручну вікно на `div` вимагало б відтворити всю цю
поведінку самотужки, і зробити це правильно складніше, ніж здається.

Додатково оброблено клік по підкладці: `dialog` займає всю область разом із
нею, тому натискання поза вмістом приходить на сам елемент.

## 9. Дані з мережі не стають розміткою

Повідомлення комітів приходять ззовні, тому в DOM вони потрапляють лише через
`textContent`. Якби картка збиралася рядком і вставлялася через `innerHTML`,
повідомлення коміту з тегами виконалося б як розмітка — це класичний XSS через
довірені на вигляд дані.

Структура картки лежить у теґу `template` в самій розмітці й клонується в
коді. Так структуру видно в HTML, її перевіряє валідатор, а JavaScript лише
підставляє текст.

## 10. Робота без JavaScript

Кнопка перемикача теми має атрибут `hidden` у розмітці, і знімає його сам
скрипт. Без JavaScript кнопки просто немає — вона не показується лише для
того, щоб не реагувати на натискання. Сторінка активності в цьому разі показує
блок `noscript` із посиланням на історію комітів безпосередньо на GitHub.
Решта сторінок від скриптів не залежать узагалі.

## 11. Помилка, знайдена під час перевірки

Після першого запуску блок помилки й ряд фільтрів лишалися на екрані, хоча в
DOM у них стояв `hidden`. Причина: атрибут `hidden` приховує елемент правилом
`display: none` зі стилів браузера, а власне правило `display: flex` у моєму
файлі має вищий пріоритет і перебиває його. Елементи з власним `display`
просто перестають реагувати на `hidden`.

Виправив загальним правилом:

```css
[hidden] {
    display: none !important;
}
```

Це один із небагатьох випадків, де `!important` доречний: правило описує не
оформлення, а службовий стан, який не повинен перекриватися нічим.

## 12. Відомі обмеження

**Ліміт запитів.** Без авторизації GitHub дозволяє шістдесят запитів на годину
з однієї адреси. При перевищенні сторінка показує зрозуміле повідомлення, але
список не завантажиться. Токен у код класти не можна: він став би публічним
разом із репозиторієм. Правильне рішення — проміжний сервер, який тримає токен
у себе, і це виходить за межі клієнтської роботи.

**Кешування.** Кожне відкриття сторінки робить новий запит. Зберігання
відповіді на кілька хвилин зменшило б витрату ліміту, але додало б окреме
питання про те, коли кеш застарів.

**Дублювання розмітки.** Шапка, бічна панель і підвал далі повторюються, тепер
уже в чотирьох файлах.

## 13. Перевірка валідатором розмітки

Після додавання `template` і `dialog` розмітку перевірено валідатором W3C.
Чотири сторінки, і цього разу перевірка не була формальністю — на сторінці
активності знайшлося три зауваження:

| Що | Чому |
| --- | --- |
| `<time data-commit-date></time>` у шаблоні | помилка: тег `time` без атрибута `datetime` мусить мати датою свій текст, а він порожній до заповнення скриптом |
| `<time data-modal-date></time>` у вікні | та сама причина |
| Порожній `<h2>` у вікні | зауваження: заголовок без тексту |

Причина спільна: елементи-заготовки порожні, бо їх наповнює JavaScript, а
валідатор перевіряє розмітку такою, якою її віддає сервер. Виправив так:
обидва теги `time` отримали значення-заглушку `datetime="1970-01-01"`, яку
скрипт перезаписує справжньою датою разом із текстом, а заголовок вікна —
текст «Подробиці коміту» за замовчуванням. Заголовок до того ж згаданий у
`aria-labelledby`, тож порожнім він не повинен лишатися й з міркувань
доступності.

Після виправлення всі чотири сторінки проходять без помилок і попереджень:

| Сторінка | Помилки | Попередження |
| --- | --- | --- |
| `index.html` | 0 | 0 |
| `about.html` | 0 | 0 |
| `activity.html` | 0 | 0 |
| `contact.html` | 0 | 0 |

## 15. Висновки

Проєкт отримав клієнтську логіку: обробку подій на перемикачі теми, фільтрі та
кнопках подробиць, динамічну побудову DOM зі шаблону й завантаження даних із

коли щось іде не так: п'ять видів помилок запиту з окремими повідомленнями,
недоступне сховище, вимкнений JavaScript. Перевірка показала й помилку в
самому CSS — приховування через `hidden` не діяло на елементи з власним
`display`.
